# 查看器评估：暂时保留现有渲染器

日期：2026-10-30。决定为**暂时保留 Three.js，继续隔离评估 NiiVue**。本轮没有运行浏览器、GPU 或性能验收，不能据此认定某个查看器更快、更准确，或永久否决 NiiVue。

已实现的来源并排比较使用现有离散体素边界渲染器和切片采样器。左右均保留 AssetIdentity，可分别选择来源、移动十字线及相机，并分别关闭联动。同一具体参考空间还必须有已记录的来源依据；相同网格、通用 “MNI” 名称和任意导入矩阵不能授权联动。用户声明与配准估计仍按原来源记录表达。空间不同或未知时，相机与坐标保持独立；不会把原生影像放进主脑模板。并排显示不更改 ROI 计算选择或保存数值。

左右点位、相机、来源身份和联动设置通过现有视图、命名视图、历史及项目格式保存。新来源选择与 ROI 计算来源分开；来源丢失会明确停止显示，删除或排除本地资产会断开对应侧。公开链接统一省略整组并排状态，反馈被省略字段，防止由私有影像、原生坐标或相机泄漏研究内容。

## 隔离候选与可复现材料

`experiments/viewer-comparison` 固定 `@niivue/niivue` **0.69.0**，上游提交 `53d450fe2e43c40c0d4ad6a2d8dc08ee37575f8c`。包锁与生产依赖完全分开。实验使用本地合成的翻轴、斜切、非等距 NIfTI、离散标签 7/42 与正负标量；两套渲染器读取同一体素和逐标签边界。Node 校验了身份、已知地标、阈值包含关系和完整项目恢复；静态打包通过并不代表已运行视觉实验。

NiiVue 的坐标 API、mesh、标量显示和事件能力值得继续试验；其原生相机表示及文档序列化不能直接替代本项目视图、原始来源与计算快照。现有 GLB、离散标签拾取与科研来源链也没有完成候选迁移验证。因此当前保留方案依据是证据缺口和兼容边界，不是性能优劣。

## 再评估条件

在允许的浏览器环境中，先运行 `tests/e2e/linked-comparison.spec.mjs`，核对同参考的两份数据、不同图谱、原生／未知空间、双向操作、取消、恢复、焦点、窄屏及 200% 缩放。再对隔离原型执行已知坐标与阈值边界、逐标签拾取、真实公共影像／表面、销毁重建及匹配工作负载性能测试；记录设备、版本、重复次数、原始样本、错误和网络请求。数据精度、配准质量与显示精度分别记录。

只有这些证据通过后，才决定继续保留、局部复用或替换。若只证明切片／格式适配可复用，决定范围仅覆盖该部分。未采用的候选能力不列为已实现功能。
