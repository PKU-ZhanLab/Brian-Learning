# Spatial QC protocol v2

This protocol separates reproducible software checks, independent anatomical measurements, and named human review. The present assessment is **partial**. No genuine independent review records have been supplied. Existing brainstem and cerebellar subdivisions remain illustrative; acquired source data are candidates only.

## Prespecified coverage

Check continuous whole-volume coverage in axial, coronal and sagittal planes, preserving slice positions and a complete coverage index rather than selecting only three central images. Check left/right orientation, midline landmarks, ventricular landmarks, cortical boundaries, and deep nuclei including original **AAL3 label 134**. Check midbrain, pons, medulla, cerebellar hemispheres and vermis separately before replacing their illustrative divisions. Do not infer whole-brain coverage from a high cortical surface association rate.

For every region record the compared asset ID, exact version/SHA-256, source/target spaces, ordered transform hashes, reference ID/version/SHA-256, annotation method, anatomical landmark definitions, boundary sampling method, units and evidence digest. An independent reference cannot be the atlas itself, its registered labels, or a segmentation generated from that same atlas. Image geometry or a shared template name cannot establish independence or alignment.

Record landmark distances and boundary distances in millimetres. Specify whether they represent mean, percentile, maximum or another statistic in the reference-specific protocol. If an independently annotated segmentation exists, also record Dice overlap in [0,1] and its sampling/resolution method. Keep missing metrics **null / unmeasured**, including missing independent overlap. Registration Jacobian, round-trip errors, content hashes, grid consistency and label preservation describe software or transformation checks; they are not anatomical accuracy measurements.

## Reference and threshold admission

`data-sources/spatial-qc/reference-set.json` is the locked input registry. Every admitted reference needs its original source URL, version, redistribution permission, actual file hash, source space, annotation method, independence basis and relationship to evaluated inputs. Acquire it separately, preserve its raw bytes, and add a distinct input lock before use. All measurement evidence must be among the locked inputs. The current `references`, `thresholds` and `measurements` arrays are empty because no independent measurements have been acquired.

Before measuring, define limits per reference, region and research task, with `basis` and `protocolVersion`; record permitted landmark/boundary statistics and interpolation. No universal submillimetre precision is asserted. Resampling a 2 mm estimated transform onto a 1 mm grid does not yield 1 mm accuracy. A reference in another space needs its own documented transform and an explicitly prepared, hashed comparison-space reference; the evaluator does not infer a space match.

## Human review

Reviewers append records containing an actual human identity/name, review date, explicit region IDs, compared asset digest, independent reference ID, evidence digest, and a pass/fail opinion. Every reviewed region also needs a `comparisonContexts` entry generated from the actual accepted comparison: exact asset ID/version/SHA/space; exact independent reference metadata including ID/version/SHA/space/annotation method; ordered transform IDs/hashes (and version/space endpoints when supplied); the full measurement, units/method metadata and evidence hash; protocol version/SHA; and the full prespecified threshold record including its evidence SHA. The context is a deep-frozen copy when created, and its canonical JSON must exactly match the current comparison. Changed reference bytes/version, transform identity/order, measurement/evidence, protocol or threshold leaves human review pending until a new matching record is supplied. A status flag or approval from another comparison cannot substitute.

Every `reviewFiles` path, including a historical review that does not qualify as human review, must resolve to a byte-verified `lockedInputs` record before it can be read for evaluation. Human review evidence hashes must resolve to separately verified locked bytes; nonexistent evidence is rejected. Measurement, protocol and threshold evidence must likewise be locked. The generated assessment retains each consumed review's path, exact file digest and raw record (identity/date/scope/context/opinion), so changed reviewer information is auditable even when the overall status stays partial. Source packaging checks the review-file locks and closes over all referenced evidence locks. Candidate review records embedded in the registry are covered by the registry's recorded digest and require locked review evidence as well.

A record labelled AI/program/agent cannot satisfy this gate. Scope outside that record stays pending. Synthetic test records exist only in unit fixtures; they are never production reviewer evidence. Software cannot authenticate a person's existence or professional qualification; a responsible human must establish those externally before admitting the record.

## Segmentation replacement

Candidates need original segmentation reference and version, resolved public redistribution permission with attribution, hashed original segmentation and label dictionary, unchanged original label IDs, source-space evidence, connected/hashed transform chain (explicit empty chain only in the same source/target space), and ordered derivation/interpolation steps. Every proposed structure needs independently measured regional checks plus actual human review **of the exact proposed output ID/hash**, not merely of the original input. The original and intermediate derivation lineage remain excluded as independent truth even while only the proposed output is eligible for measurement matching. The source validator recomputes regional gates from underlying measurements/reviews and their exact comparison contexts; supplying a `reviewed` status or a precomputed assessment alone is insufficient. Candidate data remain outside `public/` until all gates pass and a separate data change is approved.

The pinned Diedrichsen 2009 candidate contains 34 source labels, including eight vermis labels. Its pinned README states CC BY with a contributing-paper exception, the older web page describes CC BY-NC 3.0, and atlas metadata points to an absent LICENSE file. These statements are preserved for explicit version/attribution review; redistribution resolution remains pending. Matching T1/label grids do not supply independent regional QC. Brainstem Navigator was not downloaded or accepted: its agreement prohibits outside-organization redistribution. FreeSurfer is a method candidate only, with no acquired replacement output.

## Reproduction and preservation

Before first use in a fresh checkout/source package, run `node scripts/prepare-spatial-qc-sources.mjs` explicitly. The tracked `source-preparation.json` pins five official immutable raw URLs, file lengths, SHA-256 and Git blob hashes. Preparation fetches only missing files into ignored `data-cache/spatial-qc/`; it refuses redirects, hash/size mismatches, symlinks and unpinned URLs, never executes downloaded text, never overwrites existing mismatched evidence, and never writes candidates into public assets. Our prior candidate inspection and download-manifest fact JSON bytes are preserved under tracked `data-sources/spatial-qc/`; the original research output remains unchanged. Preparation verifies acquisition only, leaving licensing, independent anatomy and human review pending.

`node scripts/prepare-spatial-qc-sources.mjs --check` verifies the cache without downloading or writing. Both QC commands require that verified cache and give an explicit preparation command when it is absent; neither downloads implicitly. The source-package whitelist includes the registry, preparation manifest and both fact JSON files, while raw candidate files remain excluded. A package gate verifies that every locked input is either included source/public data or reproducible from the exact pinned cache manifest. CI performs the explicit preparation step before both QC checks. Run those steps locally when using a fresh source package; availability of the upstream host is an external prerequisite for a missing cache.

Generate only the new assessment with `node scripts/spatial-qc.mjs`. Run `node scripts/spatial-qc.mjs --check` to recompute all locked hashes, original label preservation and candidate grid/dictionary inspection and compare byte-for-byte with the saved assessment. It does not rewrite expectations. `node scripts/validate-segmentation-source.mjs --check` reports known pending candidates as structured partial and verifies their expected ineligibility; it does not assert successful replacement. `--candidate path/to/candidate.json` fails with exit code 1 unless all source and regional gates pass.

Run `node scripts/anatomy_validate.mjs --check` for the existing geometry/source invariants without rewriting its old validation report. Historical `public/data/aal-v3/root-review.json`, registration reports/figure, original candidate downloads and their manifests stay unchanged. Assessment inputs include protocol and software digests, actual byte counts/hashes, asset versions and transforms; generation has no wall-clock timestamp so repeated checks are deterministic. Changes require explicit input lock updates and regeneration, preserving previous evidence in version history. No new reference, automated result or human review is inferred from a successful build or unit test.
