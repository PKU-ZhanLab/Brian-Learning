# Evidence v2

`src/lib/evidence-schema.js` owns the runtime model and migration; shared JSDoc types live in `src/lib/research-contracts.js`.

The `brain-evidence-v2` bundle contains `dataVersion`, `references`, `readings`, `experiments`, `results`, `locations`, `claims`, `mappings`, `sourceArtifacts`, `reviewEvents` and `relations`. Collections use stable IDs. Results link locations and claims by ID. Mappings express E1 source-to-target support; relations express agreement, disagreement, complementarity or non-comparability between results.

`Reported<T>` has either `state: 'reported'`, `value` and `sourceRefs`, or an explicit missing state (`not-reported`, `not-extracted`, `uncertain`, `not-applicable`), `reason` and `sourceRefs`. Zero, empty text and ordinary defaults never represent missing evidence. Effect estimates contain independent reported/missing variance and interval fields; migration never computes an effect from t, p or an image.

Samples separate enrolled, included and per-analysis n. Statistics retain type, value, degrees of freedom, unit, p operator and source anchors. Time windows use ms; frequency bands use Hz. Corrections retain method, comparison family, pass/fail and threshold. Locations use mm and retain the reported source label and source space. `uncertainty` represents localization uncertainty; optional `dispersion` preserves between-subject coordinate SD/SE separately. Neither implies registration precision. Derived assets retain `AssetIdentity`; transforms retain an explicit reference or null.

`migrateEvidence(input, options)` is a pure migration preview. It accepts v1 or v2 and returns `{value, warnings}`; invalid input throws. v1 originals, unnormalized fields and text are retained in `legacyV1`, both at bundle and record level. A v1 result has no independently established experiment: `experimentId` stays null. Existing reading summaries migrate as reading claims with null experiment/result IDs, never as extracted experimental results. The original eight generic MNI points remain `MNI-unspecified`.

`validateEvidenceV2(input, options)` returns a validation report without mutation. `validateEvidence` in `evidence-workspace.js` delegates to this boundary and accepts both versions. Options can supply known reference/result IDs or records for local-only overrides. `mergeEvidence` deduplicates DOI and rewrites active reference edges across all collections. Historical top-level v1 snapshots remain the original input; incoming originals are preserved in `legacyImports` instead of being overwritten by DOI normalization. Selected-paper UI exports omit these package-wide snapshots to exclude unrelated papers while preserving each exported record's own `legacyV1`. Schema validation checks shape and provenance links; it does not establish that a transcription agrees with the primary paper. Source-artifact semantic auditing belongs to E4.

`ReviewEvent` records the subject, independent stage, actor type/name, date, scope, source references, limitations and record version. An AI source check never produces human review. Human review needs an identified human, valid date, nonempty scope and version. `deriveReviewState(events)` aggregates only the events supplied by its caller; it does not infer higher stages. `getResultViewModel(resultId, bundle)` selects events for that result/version and derives coordinates from locations, preserving legacy text for display. Missing source materials are recorded as limitations while historical check events remain available. The built-in v2 numerical additions do not create any fresh checking event.

The existing text editor consumes this same result view model. `resultViewModelToEvidence` converts edits at the single migration boundary, preserves structured fields the editor cannot edit, and assigns a new record version. Historical checks cannot certify the changed result. `removeEvidenceRecords` removes explicitly selected records and dependent edges. The current UI exports v2 records, never a separate display schema; complete source artifact closure/export policy is extended by E5.

The editor's pure state/submission boundary is `src/lib/evidence-editor.js`. It initializes fresh check intent separately from inherited statuses, with blank reviewer/tool name, date and scope. A deliberate check selection or recheck action records the selected result/coordinate IDs; changing content revokes the affected intent. `prepareEvidenceEditorSubmission` sends `{record, reviewIntent}` through the UI save callback. The adapter validates that intent and creates `source-checked` events on the new record version using the supplied actor type/name/date/scope and each selected record's source link. Human actor identity still creates only a source-check event. The editor cannot create `human-reviewed` events. No fresh intent means the new version remains unchecked while original history stays intact.

`loadEvidence` reads `brain-model.evidence.v2`, then the old `brain-model.evidence.v1` when no v2 item exists. Reading v1 does not write either key. A successful explicit save writes only v2; v1 remains available. Invalid input or storage failure leaves the old bytes intact. A corrupt present v2 record is reported, never silently replaced by v1.

The frozen v1 fixture is `tests/fixtures/evidence-v1-baseline.json`, SHA-256 `76078639bb42e23994695d9e6bf922f8200a6305e9e818fe29a7c1e24ac91c2a`. The portable v2 example in `data-sources/results/curated-results.json` matches `curatedEvidence` from `src/data/results.js`; its four `curatedResults` display rows are derived through `getResultViewModel`.
